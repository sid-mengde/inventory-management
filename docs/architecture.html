Factory Inventory Management System — Architecture

Full-stack demo: Vue 3 frontend, FastAPI backend, in-memory JSON data. No database, no auth backend.

Vue 3 · Composition API FastAPI Pydantic In-memory data No database

Tech Stack

Frontend

Vue 3 + Vite

  • Composition API throughout
  • vue-router (client-side routes)
  • axios (HTTP client)
  • Custom SVG charts, CSS Grid layouts
  • i18n via useI18n (en / ja)
localhost:3000
Backend

Python FastAPI

  • Pydantic models for request/response validation
  • Query-param based filtering (no ORM)
  • CORS wide open (allow_origins=["*"])
  • Single-file app: server/main.py
localhost:8001
Data

JSON Files

  • Static files in server/data/*.json
  • Loaded into memory once at startup
  • Loader/aggregator: server/mock_data.py
  • No persistence — restart reloads from disk

System Diagram

Request / Filter Data Flow

1

User adjusts a filter

Time Period, Warehouse, Category, or Order Status changes update shared refs in the useFilters composable (singleton state used across views).

2

View calls api.js

getCurrentFilters() builds a plain filter object; the relevant api.getX(filters) method turns it into a URLSearchParams query string, skipping any filter set to "all".

3

FastAPI applies filters

Shared helpers apply_filters() and filter_by_month() in main.py filter the in-memory lists by warehouse, category, status, and month/quarter.

4

Pydantic validates the response

Each endpoint declares a response_model (e.g. List[InventoryItem]), so the filtered dicts are validated and serialized before returning JSON.

5

Vue stores raw data, derives the rest

Responses are stored in raw refs (e.g. allOrders, inventoryItems); everything the template renders is a computed() derived from those refs, so it recalculates only when dependencies change.

Things to Know

!

api.js calls /api/tasks and /api/purchase-orders (create/get), but neither route exists in server/main.py — those calls 404 until implemented.

!

useAuth is fully mocked — isAuthenticated is hardcoded true and logout just shows an alert. There is no real login flow or auth boundary.

!

All data is in-memory: edits made through the API are lost on backend restart, since everything reloads fresh from server/data/*.json.
